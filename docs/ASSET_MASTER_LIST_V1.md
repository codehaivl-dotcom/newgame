## Meaning of fields

- `GEN`: concept illustration appropriate for Image-to-3D candidate; separate asset, no integrated VFX.
- `CODE`: geometry/material/procedural in-engine or Blender recommended; concept reference optional, no need to spend 3D model credits.
- `VFX`: 2D/shader/particle work; not a 3D model generation target.
- `P0`: first production wave or essential; `P1`: later within approved art plan; `P2`: extension **not** permission to implement new gameplay features.
- `PLANNED`: not generated. Nothing is considered saved until its real repository path is recorded.

## Review & file rules

1. Every asset has one immutable ID. A different silhouette or weapon is a new revision, not a silent replacement.
2. Image review happens **in chat**: approve/reject explicitly, then update the manifest and log in the repo. Never mark approved just because an image was produced.
3. Approved source sheet: `assets/sheets/<group>/SHEET-<GROUP>-NNN_vNN.png`; cropped piece: `assets/crops/<group>/<ID>_vNN.png`; model: `assets/models/<group>/<ID>_vNN.glb`. Only paths to real committed files may be filled in.
4. For image-to-3D, props must not share geometry, shadows, stands or VFX. Hero source art is **one character per image** in STRICT frontal **T-pose**, both arms horizontal 90° ±5°, hands entirely empty, no weapon/items/VFX or detachable backpack attached.
5. Keep production records machine-readable in `assets/asset_manifest.json`; narrative record is `docs/PRODUCTION_LEDGER.md`.

See [image specification](IMAGE_RENDER_SPEC_V1.md).
